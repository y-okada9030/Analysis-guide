# 更新とミッション章の追加

解析日に公式手順の版、校正更新、既知の不具合を照合します。古いコマンドを現行推奨として残さないよう、変更点は章の冒頭に日付と根拠を記載し、関連するコードブロックを更新します。

新しいミッションには `docs/missions/<mission>/` を設け、概要、データ取得、再処理・screening、画像と領域、スペクトル・背景・応答、検証、参考文献の順で追加します。機器が複数ある場合は XRISM のように機器別ページを分けます。共通の FITS・XSPEC の説明は複製せずリンクします。

コマンドを掲載する際は、公式文書で引数の順序と現在の版を確認し、端末と対話ツールの入力を区別し、コマンドを fenced code block に入れます。観測 ID、座標、領域、背景、モデルの固定値は「公式チュートリアル例」または置換値として示し、一般の推奨値と混同させません。

文章変更後はローカルプレビューと厳格ビルドを通します。

```sh
mkdocs build --strict
```
