# スペクトル解析と結果の確認

スペクトルを作っただけでは解析は終わりません。線源 PHA、背景 PHA、RMF、ARF が**同じ観測・時間・領域・イベント選択**を表しているかを確認し、目的に合う統計量とモデルで評価します。広がった線源では、背景の選択と応答の空間的な重みが温度、元素量、フラックスなどの結果に直接影響します。

## ファイルの対応を確認する

PHA ヘッダーの `BACKFILE`、`RESPFILE`、`ANCRFILE`、`BACKSCAL`、`EXPOSURE` を読みます。`BACKSCAL` は線源領域と Background 領域の面積や有効面積の比に関わるため、異なる座標系で描いた領域や別観測の Background を入れると値が不自然になり得ます。応答を作り直した場合は、PHA が古い応答を指したままになっていないかも確認します。

```sh
fkeyprint <SOURCE_PHA> BACKSCAL
fkeyprint <SOURCE_PHA> RESPFILE
fkeyprint <SOURCE_PHA> ANCRFILE
fkeyprint <SOURCE_PHA> BACKFILE
```

上の入力は HEASoft 環境での確認例です。Chandra なら CIAO の `dmlist` や `dmkeypar` でもヘッダーを確認できます。背景ファイルを指定しない場合は、その理由と、背景を別成分としてモデル化するかを記録します。

## XSPEC に読み込む

XSPEC は [公式マニュアル](https://heasarc.gsfc.nasa.gov/docs/software/xspec/manual/) に従って使います。PHA のヘッダーに背景・応答への正しい参照が書かれていれば、まず PHA だけを読み込み、XSPEC が参照したファイルを確認します。以下は **端末**で起動し、続いて **XSPEC 内**で入力する最小例です。

```sh
xspec
```

```text
data <SOURCE_PHA>
show data
plot data
```

ヘッダーの参照がない、または別のファイルを使う科学的理由がある場合は、対応する Background・応答を明示します。`<...>` は実在するファイルに置き換えます。

```text
backgrnd <BACKGROUND_PHA>
response <SOURCE_RMF>
arf <SOURCE_ARF>
show data
```

広がった線源のスペクトルは場所によって変わり得ます。熱的プラズマ、非熱的放射、吸収などのどの成分を入れるかは、観測帯域と研究目的から決めます。元画像で定義した各領域と、フィットに使う PHA の範囲を対応づけます。

## 統計量と Background の扱いを決める

カウントが少ない帯域や高分解能の線を扱うとき、見やすくするための強いグルーピングで情報を失う場合があります。統計量とチャンネルのまとめ方は [XSPEC の公式マニュアル](https://heasarc.gsfc.nasa.gov/docs/software/xspec/manual/) を読み、背景を差し引くかモデル化するかと合わせて選びます。特に Resolve では一つの線の形が結果を左右するので、グルーピング後の見た目だけで決めません。フィット結果とともに、使用エネルギー帯、固定パラメータ、統計量、背景の扱いを残します。

複数 ObsID や複数機器のスペクトルを扱うときは、観測ごとの PHA、背景、RMF、ARF を維持して同時にフィットするか、公式手順で結合します。スペクトルだけを加算し、最初の観測の応答を全体にコピーしてはいけません。異なる機器の規格化差や、抽出領域の違いも検討します。

## 結果を点検する

フィットが終わったら、データとモデル、残差を表示します。特定の線やエネルギー帯に系統的な残差があれば、モデルだけでなく背景、応答、校正、イベントのグレード、領域選択も見直します。

```text
plot ldata delchi
```

最終的に、元イベントと露出マップ上で領域を再表示し、観測ログ、スクリーニング、背景の規格化、応答の生成入力、フィットの実行記録をそろえます。図を平滑化した場合は、解析に使った元データと分けて保存します。第三者が再現できるのはコマンドの列だけでなく、**各分岐で何を選んだかが分かる記録**があるときです。
